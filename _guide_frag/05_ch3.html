3. Your First Program

BEGINNER

3.1 Hello, World!

Create a file named hello.cn:

// The classic first program
main {
    printin("Hello, World!")
}

Run it from a terminal in the same folder:

cnext run hello.cn

You should see Hello, World! printed to the screen.

Key point main { ... } is where every standalone program begins. Everything between the braces runs, top to bottom, when the program starts.

3.2 Understand Every Line

PieceMeaning
// ...A comment. The compiler ignores it; it is a note for humans.
mainThe entry-point function, run automatically.
{ ... }A block — groups statements together.
printin(...)A built-in function that prints text and then a new line.
"Hello, World!"A string literal — a sequence of characters.
Theory — What "running" a program means When you type cnext run hello.cn, the compiler does the five jobs from Chapter 1 (lex, parse, analyze, generate C, compile to native) and then executes the result. The operating system loads your program into memory, hands it to the CPU, and the instructions in main run in order — exactly once.

3.3 Create a Real Project Folder

Instead of a loose file, scaffold a project:

cnext new my_first_app
cd my_first_app
cnext run src/main.cn

This creates a tidy layout — source in src/, a cnext.toml configuration, and space for packages and tests. Professional codebases organize files like this from day one.

3.4 run vs. build

cnext run file.cn compiles and immediately runs your program — perfect for iterating. cnext build file.cn compiles and leaves a standalone executable you can ship or run later, which is what release software does. 

cnext run hello.cn       # compile + run now
cnext build hello.cn     # compile only, produce an executable
./hello                  # run the produced executable

3.5 The REPL: Try Before You Write Files

A REPL is an interactive prompt that reads your input, evaluates it, and prints the result — useful for experimenting: 

cnext repl
> printin("testing")
testing
> 1 + 1
2
> exit
Real world Every serious language ships both a "build once, run anywhere" path for production and a fast feedback loop for development. Cnext’s REPL is that feedback loop; the compiler producing an .exe is the production path.
