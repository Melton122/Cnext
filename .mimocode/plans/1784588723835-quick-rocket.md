## Changes

### 1. Add `len()` builtin function

**Files:** `src/semantics.c`, `src/codegen_expr.c`

`len()` is documented in the README and used in tests but never implemented. It causes 2 SKIP tests.

**semantics.c** - After line 27 (after `free_token` registration), add:
```c
Token len_token = {TOKEN_IDENTIFIER, "len", 3, 0};
define_symbol_if_missing(len_token, TOKEN_FUNC, true, NULL);
```

**codegen_expr.c** - After the `is_free` check (line 286), add:
```c
bool is_len = (node->left->token.length == 3 && strncmp(node->left->token.start, "len", 3) == 0);
```
Then after the `is_free` block (line 299), add:
```c
} else if (is_len) {
    fprintf(out, "(int)(");
    generate_expression(node->children[0]);
    fprintf(out, ".length)");
}
```

This generates `(int)(expr).length` for both strings (CnextString) and arrays (generated structs with `.length` field).

### 3. Add `// EXPECT:` annotation support to the test runner

**Files:** `src/main.c`, `src/main_utils.c`, `include/main_internal.h`

The test runner ignores `// EXPECT:` comments and only checks exit codes. This causes 2 FAIL tests that are actually correct (they're negative/runtime-error tests).

#### 3a. Add EXPECT parser (`src/main_utils.c`)

```c
#define MAX_EXPECT_LINES 64
#define EXPECT_LINE_MAX 1024

typedef struct {
    char text[EXPECT_LINE_MAX];
} ExpectedLine;

int parse_expect_lines(const char* source_path, ExpectedLine* out, int max);
```

Reads the source file line by line, finds lines matching `// EXPECT: <text>`, and populates the output array.

#### 3b. Add stdout/stderr capture (`src/main_utils.c`)

```c
int run_process_captured(const char* program, char* const args[],
                         char* output_buf, size_t output_buf_size);
```

On Windows: redirect stdout+stderr to a temp file via `_tempnam` + `freopen`, read back after `_spawnvp`.
On Unix: use `pipe()` + `dup2()` to capture stdout+stderr, read from pipe after `waitpid()`.

#### 3c. Rewrite test loop (`src/main.c`, lines 415-482)

For each test file:
1. Read source, parse `// EXPECT:` annotations
2. If EXPECT annotations exist:
   - Compile with `test_mode=true` (so `assert` in test blocks doesn't call `exit`)
   - Run with `run_process_captured()` to capture output
   - Check every expected string appears in the captured output
   - PASS if all expected strings found (regardless of exit code)
   - FAIL with details if any expected string missing
3. If no EXPECT annotations: current behavior (exit code check)

### 4. Fix cross-platform `doctor` command

**File:** `src/main.c` (lines 563-578)

The `doctor` command uses `>nul 2>&1` (Windows-only). On Linux/macOS this creates a file called "nul".

Use the already-defined `CNEXT_PATH_SEP` and platform detection:
```c
#ifdef _WIN32
    #define DEV_NULL "nul"
#else
    #define DEV_NULL "/dev/null"
#endif
```
Then replace all `>nul 2>&1` with `>" DEV_NULL " 2>&1`.

### 5. Fix cross-platform `cache` command

**File:** `src/main.c` (lines 615-621)

The `cache` command uses `rm -rf` and `ls -la` (Unix-only). On Windows these fail silently.

Add platform-specific handling:
```c
#ifdef _WIN32
    system("rmdir /s /q .cnext\\cache 2>nul");
#else
    system("rm -rf .cnext/cache 2>/dev/null || true");
#endif
```
